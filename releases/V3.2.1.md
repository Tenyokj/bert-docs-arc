# BERTDAO V3.2 - Reviewed Delivery, Admin-Controlled Payments and V3.2.1 Hotfix

**Release tag: `v3.2.1` | Arc Testnet, chain ID 5042002 | V2 remains V2.3**

This release closes the V3.2 development cycle, including the final V3.2.1
correction-liveness hotfix. It covers Community governance, dApp reliability,
dependency security, browser E2E, indexing, deployment and documentation.
It is a testnet release, not a mainnet launch or an independent security audit.

## Community Layer: What Changed Since V3.1

All four lanes share the updated execution flow: **Admin Binary, Member Binary,
Admin Slate and Member Slate**.

- **Independent milestone review:** the execution recipient cannot approve or reject its own work. Its support is excluded from the review weight and reviewer count, while its financial refund rights are retained.
- **Admin quorum for every payment:** winner settlement opens a fixed 20% authorization, rather than transferring funds immediately. Supporter approval opens each later 40% authorization. Every transfer separately needs current Admin approvals.
- **Current-role authorization:** approvals bind to the Admin's role-incarnation nonce. Removing and reappointing an Admin does not revive an old approval. Execution requires a sorted, unique, threshold-sized witness.
- **Fixed recipient and budget:** payment relayers cannot redirect funds or increase an authorized amount. Protected plan reserves are not free Treasury execution balance.
- **Bounded payment liveness:** approval and actual payment must complete within seven active Community days. Permissionless expiry makes the entire unpaid execution budget refundable: 100%, 80%, or the remaining approximately 40%. Pause freezes the Community clock.
- **Separate validator accounting:** validator rewards remain reserved separately. Neither payment expiry nor failed-plan refunds consume them; already paid tranches are not clawed back.
- **Actual payment defines progress:** the next proof clock begins after payment, not merely proof approval. Final approval alone does not complete the plan before its final transfer.

### V3.2.1 Correction Hotfix

Expanded local browser E2E reproduced a real liveness defect in the original
V3.2.0 Manager: review plus cooldown could outlast the original proof window,
and an absent executor could leave correction stuck.

Manager **2.0.1** now fixes the correction deadline at first rejection:
**rejection Community time + 48-hour cooldown + configured proof duration**.
Reopening cannot extend that deadline. Anyone may expire an overdue correction
cooldown through the Hub without waiting for the executor to reopen it.
The one-correction limit, 20/40/40 schedule and unpaid-only refunds are unchanged.

## dApp and Wallet Reliability

- Community setup pins creator, chain, Factory, library and the original immutable configuration across Reserve Treasury, Deploy Hub and Activate.
- A confirmed reservation can be resumed from its transaction hash. Read-only checks recover the original configuration, Treasury and matching Hub rather than issuing another deployment blindly.
- Submission locks, receipt reconciliation and pending-nonce checks reduce duplicate actions after ambiguous wallet/RPC responses. An `already known` response is not automatically labeled a contract revert or retried with a higher nonce.
- V2 settlement follows network block time rather than the visitor's computer clock. Confirmed writes refresh relevant plan/proof state.
- Corrected-proof eligibility is attempt-aware. Membership exits check both author obligations and voting/milestone locks; archive checks read the modules that own those obligations.
- Role-event fallback reads Membership events; receipt-related reload timers are cancelled when their components unmount.
- Factory-qualified URLs keep identically numbered Communities distinct. Historical numeric Arc bookmarks remain pinned to original V3.1.
- Production builds no longer hide TypeScript errors with `ignoreBuildErrors`.

## Indexing, Console and Documentation

Graph **v3.2.1** retains V3.1, V3.2.0 and V3.2.1 Factory sources with their real
deployment blocks. Corrected proof attempts reset indexed review tallies; grace
within the same attempt preserves votes. Actual Paid events are distinguished
from proof approval and payment readiness. The hotfix changes no event signature
or Graph schema.

Console **V0.1.0 Beta** monitors the current bundle alongside historical contracts,
including proxy implementation/admin reads. Its RPC/V2/V3 health was checked
after publication.

Repository documentation, dApp explanations, tester/contributor guides and
deployment records were reconciled. Whitepaper **1.3.2** contains separate V2/V3
parts, the current address appendix and the correction-hotfix boundary.
V2's executable legacy **30/40/30** round policy is explicitly distinguished from
new **20/40/40** backer-governed rounds; this cleanup is not a V2 semantic upgrade.

## Dependency Security and Verification

Next.js was patched to **16.4.3**. Compatible wallet, Core tooling and Graph CLI
dependency updates were verified through clean lockfile installs, tests and builds,
without blindly forcing incompatible major upgrades. The Graph CLI archive
extraction replacement was checked against valid and malicious archive fixtures.
Remaining advisories are documented, not blanket-dismissed.

Final source verification recorded:

- **237 Core tests**, including **16 targeted Manager regression tests**.
- **65 frontend regression/source-guard tests**, with frontend and Console production builds passing.
- Combined local browser E2E: **163 V3 UI transactions + 60 V2.3 UI transactions = 223 confirmed receipts**.
- **44 expected negative contract checks** simulated read-only; **25 V2 queue-fixture receipts** identified separately from UI activity.
- V2 coverage included successful grants and progressive fees, losing-pledge refunds, no-quorum cancellation and rounds without a viable winner.
- V3 coverage included all four lanes, payment quorum, independent review, correction/rejection, unpaid-budget refunds, pause-aware clocks, membership locks, validator rewards and Admin actions.
- V3 subgraph codegen/build passed with all three modular Factory sources retained.

These are bounded tests against real contracts on a disposable local chain,
not exhaustive validation of every browser, MetaMask/WalletConnect integration,
public-chain user flow or possible state. No completed new public V3.2.1
Community pilot is claimed.

### Security Status, Without Ambiguous Counts

The saved full-project Slither run contains **229 detector results**:
**6 High, 17 Medium, 78 Low, 117 Informational and 11 Optimization**.
In the changed **CommunityMilestoneManager alone**, one Low `calls-loop` result
remains for bounded current-Admin role/nonce reads. These are different scopes.
Access controls, reentrancy guards and malicious-token regressions inform internal
triage; they do not prove every warning unreachable. Dependency audit also retains
documented advisories. There is no independent audit or mainnet readiness claim.
