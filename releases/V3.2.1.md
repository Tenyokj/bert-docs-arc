# BERTDAO V3.2.1 - Community Correction Hotfix

**Arc Testnet only (chain ID 5042002). V2 remains V2.3.**
This patch releases a new Community infrastructure bundle with
`CommunityMilestoneManager` **2.0.1**. It is not an in-place upgrade of existing Communities.

## What Changed

- First rejection now fixes the correction deadline at rejection Community time + 48-hour cooldown + configured proof duration.
- Reopening a correction cannot extend that deadline.
- Anyone may expire an overdue correction cooldown through the Hub, even if the executor never reopens it.
- The existing 20/40/40 schedule, supporter review, execution-recipient exclusion, per-tranche Admin quorum and validator accounting are unchanged. Only unpaid execution capital becomes refundable on terminal failure.

Historical immutable V3.2.0 Managers retain the earlier correction liveness defect.
Use the new Factory for corrected pilots; memberships, votes and funds are not migrated automatically.

## Verification and Limits

Pre-deployment verification: **237 core tests**, including **16 Manager regressions**;
combined local browser E2E with **223 confirmed UI transactions** and **44 read-only
negative checks**. Rollout checks additionally passed **65 frontend regressions**,
frontend/Console production builds and three-Factory subgraph codegen/build.

Slither is not clean: **229 findings** remain in the analyzed contract set, including
the Manager's bounded Low `calls-loop` item. These results are not an independent
audit, a completed new public Community pilot or a mainnet readiness claim.
Arc Demo verification does not establish personhood or Sybil resistance.
